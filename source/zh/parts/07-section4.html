04 · Data Model

数据模型：事件、人物、关系、解释

记忆系统的第一张表，决定了它以后能问出什么问题。

如果系统只存“对话片段 + 向量”，它只能回答“哪段话最像”。如果它存“事件 + 人物 + 参与 + 关系 + 解释”，它就能回答“上次见面他答应过什么”“个体对他的判断有没有依据”“这件事和那件事是不是同一件”。数据模型不是实现细节，它决定了系统的认知上限。

4.1 事件：记忆的原子单位

事件不是一句对话，也不是一整天。它是一段有边界、有参与者、有经过、有结果的经历。事件分段可以靠预测误差的峰值、目标切换、场景变化、对话主题的转折来检测。一个事件记录至少应包含以下字段：

表 6 · Event 记录
字段含义示例 / 约束
event_id全局唯一、不可变ULID；一旦写入不复用
time开始/结束时间、时区、时间精度不确定时存区间，不强行精确

participants参与者、角色、身份确定度人物 ID + confidence + candidates

4.2 人物、参与、关系：三张表，不是一张表

人物档案回答“他是谁”；参与记录回答“他在这件事里做了什么”；关系摘要回答“双方现在是什么关系”。三张表分开，理由很简单：一个人可以参加很多事，一段关系可以被很多事支持，但一次互动不能直接等于关系。

表 7 · 人物 / 参与 / 关系
对象关键字段设计要点
Personperson_id、称呼/别名、识别线索（人脸/声纹/称呼）、已知特点、首次/最近出现身份不确定时保留候选，不强行合并
Participationperson_id、event_id、角色、动作、回应、共同出现还是实际互动、来源、置信度“同框”不等于“互动”；“他说”不等于“他做”
Relationship熟悉、亲近、信任范围、合作、承诺、边界、社会角色；每维带 value、evidence_event_ids、scope、confidence、updated_at“个体信任他”与“他信任个体”分开；判断带依据

关系是多维的，不是“好/坏”一根轴。一个人可能“工作信任高、私人亲近低、承诺记录好、边界感强”；另一个人可能“亲近高、信任低、合作一般”。把关系压成一个分数，会丢失最有用的信息。每个维度都要有证据事件、适用范围（工作/家庭/公共）与更新时间；没有证据的判断只能标为推测。

4.3 解释层：事实与解释分开，解释可修正

“他没有回复请求”是事件；“他不在乎”是解释。两者混在一起，系统就会把一次行为固化成一个人的本质。解释层单独存储，至少包含：

Interpretation {
  interpretation_id,
  target_event_id,
  perspective: self | other,
  type: feeling | speculation | attribution | evaluation,
  content,
  confidence,              // 0–1，不是“真/假”二元
  basis_event_ids: [],     // 这条解释由哪些事件支持
  created_at, updated_at,
  supersedes: interpretation_id | null,
  status: active | revised | retracted
}

关键规则：解释可以修正，但不能覆盖历史。当新信息到来时，创建新版本并指向被修正的旧版本；旧版本保留，用于审计“当时为什么这么想”。这不仅更诚实，也更有用：它让系统能解释自己的判断变化，而不是假装一直很聪明。

4.4 知识、记忆、技能：同一事件的三类积累

表 8 · 三类积累与习惯缓存
类型回答字段晋升条件
Memory一个人经历过什么事件日志 + 人物/参与/关系 + 解释版本；共享 event_id事件写入即成立；不晋升为“知识”

Habit类似情境下上次怎么做情境签名、缓存模板/技能 ID、状态（candidate / ratified / revoked）、proposed_by、ratified_by、频次、成功率、最近使用、rollback_to高频重复 + 结果稳定；后台只提案，主脑批准；只缓存模板，不缓存决定

记忆是事件与关系的直接记录；知识是从多个事件抽象出的规则；技能是程序化步骤。三者共享同一个 event_id，但分别更新。习惯不是第四类积累，而是高频路径的缓存；它只加速情境组装，不替代记忆、知识或技能。

“一次成功不足以形成稳定技能，一次主观判断不应直接变成确定知识。”这条来自版本一的约束，应该写进晋升规则，而不是靠模型自觉。它也是防止系统把偶然当规律的最后一道闸。

4.5 情境包：唯一跨层接口

情境包不是“摘要”，而是为当前决策裁剪过的最小情境。它的槽位数量硬性限制在 4±1，每个槽位有类型、内容、来源、置信度与 TTL。推荐 schema：

ContextPacket {
  packet_id, turn_id, created_at, expires_at,
  governance_mode: companion | engineering,
  self: {
    ratified: { values[], role, long_term_goals[], active_commitments[] },
    pending: [ { proposal_id, type, summary, evidence_count, expires_at } ]
  },
  who: { person_id, name, identity_confidence, candidates[] },
  relationship: {
    dimensions: { familiarity, closeness, trust_scope, cooperation,
                  commitment, boundaries, social_role,
                  social_safety, belonging_need },
    basis_event_ids[], scope, confidence, updated_at
  },
  experiences: [
    { event_id, one_line, why_relevant, source, confidence }
  ],
  omitted: { count, topics[], event_ids[] },   // 被筛掉的候选
  scene: { place, activity, time, atmosphere },
  goal: {
    current, priority, success_criteria,
    scope: turn | constitutional,   // 只有 constitutional 需要批准
    provenance: { proposed_by, ratified_by, ratified_at, proposal_id },
    lock: none | dual_ratified | user_sovereign | constitutional   // 仅对 constitutional 生效
  },
}
// 构成性只读指针与其余槽位
ContextPacket (续) {
  constitution_ref: { version, ledger_head },
  commitments: [ { content, due, status, counterpart } ],
  changes: [ { what_changed, since_when, source } ],
  uncertainties: [ { question, candidates[], evidence_needed } ],
  affect: { valence, arousal, confidence },
  state_view: {
    goal_pressure, relationship_strain, resource_load, uncertainty,
    unresolved_commitments, impact_gap
  },
  state_params_ref: { schema_version, params_version, state_hash },   // 参数在 runtime，不进上下文
  budget: {
    slots: 4, header_tokens: 300, slot_tokens: 600,
    tokens: 900, detail_level: brief|standard|deep
  }
}

这个 schema 里没有 advice、没有 recommendation、没有 action。它不是“给主脑出主意”，而是“把主脑需要知道的事实、关系、目标与不确定性准备好”。主脑可以要求 EXPAND(event_id) 展开细节，也可以要求 VERIFY(claim) 核查来源；但它不能要求后台“代替它决定”。

4.6 证据账本：反复回想不等于多次证据

大模型记忆系统最容易犯的错误，是“自我强化”：同一段摘要被反复检索、反复改写，最后系统以为它被很多独立来源支持。人脑也有类似问题：反复回想一件事，会提高它的可及性，但不会把它变成多次独立经历。解决方法是证据账本：

  • 证据按 event_id 计数，不按检索次数计数。evidence_count = distinct(event_id)；同一事件被召回一百次，仍然只是一条证据。
  • 来源分层：亲历 > 一手文档 > 他人转述 > 推断 > 模型生成。高一层可以覆盖低一层，但必须保留原始来源。
  • 解释与事实分账：解释的置信度不能因为“被多次引用”而上升，只能因为“出现新的独立事件”而上升。
  • 矛盾不平均：两条冲突记录都保留，标 contradicts；检索时同时返回，由主脑看到冲突，而不是系统偷偷选一个。
一句话 记忆系统的可信度，不取决于它记得多流畅，而取决于它能否在每一次断言后面放上一个可核对的事件编号。
