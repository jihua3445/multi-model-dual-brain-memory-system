02 · From Mechanism to Primitive

从神经机制到计算原语

不要直接把“海马体”写成一个 Agent；先把它解决的问题翻译成一个计算原语。

把脑区直接映射成 Agent，是这类方案最常见的偷懒。海马体不是“一个检索服务”，前额叶也不是“一个规划 API”。更有用的做法，是先把每个机制还原成它解决的计算问题，再选择合适的技术实现。下面这张表，是整份方案的核心翻译表。

2.1 五条设计定律

从这张表可以提炼出五条比“架构图”更耐用的定律。它们不是神经科学的结论，而是从机制中推出的工程约束。

第一定律
写入越便宜，遗忘越昂贵。如果所有输入都无条件写入，检索的噪声会指数上升，最终不得不靠更大的模型、更长的上下文来弥补。编码门控不是可选项，是成本控制的第一道闸。
第二定律
索引越稀疏，重建越灵活。索引只存指针与稀疏码，内容留在事件日志与语义库中。这样同一段经历可以被不同任务以不同方式重建，而不是被一种摘要锁死。
第三定律
巩固越像睡眠，泛化越好。在线学习容易过拟合当下；离线重放、聚类、抽象才能把“这一件事”变成“这类事”的规律。没有离线巩固的系统，只有日记，没有知识。
第四定律
提取越带来源，虚构越少。重建是必要的，但重建必须能回溯到原始片段。来源标签、证据计数与弃权策略，是防止“流畅的胡说”的三件套。
第五定律
关系越靠近决策，记忆越有用。记忆的价值不在于“能被检索”，而在于“能在正确的关系与目标下被唤起”。人物—事件—关系图不是附属功能，而是检索的主索引之一。

2.2 不应当模拟的东西

“像脑”不等于“复制脑的所有缺陷”。有三类机制不适合直接工程化：

  • 临床上的记忆异常与创伤性记忆。它们不是“特性”，不应作为设计目标；系统应优先可审计、可删除、可解释。
  • 情绪性偏见与动机性推理。人会自动把有利于自己的解释记得更牢；工程系统若刻意模仿，会放大操纵与偏见。可以模拟“情绪权重”，但不能模拟“自欺”。
  • 意识的神经相关物。本方案中的主脑是一个功能性的决策中心，不声称具有主观意识；双脑、潜意识、多核都只是工程类比。

2.3 证据分级：哪些结论可以信到什么程度

神经科学证据不是一块铁板。有人类脑损伤与干预研究，有动物光遗传与药理实验，有人类影像的相关证据，也有纯粹的计算模型。把它们混在一起，很容易得出“脑是这样，所以系统必须这样”的假推论。下面给出一张粗略但实用的证据分级表：

使用这张表时，建议遵守三条规则：只把 A/B 当作机制依据，把 C 当作约束与灵感，把 D 当作设计隐喻；动物范式必须标注物种与任务，不能直接推人类；每一个被引用的机制，都要能对应一个可消融的工程模块——否则它只是修辞，不是设计。

2.4 预测加工：一个统一的目标函数

预测加工把编码、提取、再巩固、巩固、遗忘与决策串成一个目标：脑是不断生成预测、并用精度加权误差更新自身的模型。记忆不是模型的副本，而是模型本身及其被环境修正的历史（Rao & Ballard 1999；Friston 2010；Clark 2013）。

最简形式：ε = observed − predicted，surprise = precision · ε²。高精度误差才值得改写模型；低精度误差进入短缓冲或习惯化。三条设计含义：只更新高精度误差，避免噪声改写关系；精度不是召回次数，反复想起只提高可及性；冲突降低精度，双方并列展示，不平均成一个“更可信”的结论。

encode_threshold      -= 0.2 * surprise
consolidation_priority += 0.2 * surprise

提取是后验推断：P(h|c) ∝ P(c|h)·P(h)。向量近邻只提高似然，人物、时间、地点、因果等结构证据才提高先验；否则语义联想会被误判为情景记忆。遗忘是按“需要概率”重新分配检索资源；事件分割按预测误差峰值或目标切换切分；决策可用期望自由能 G = risk + ambiguity − expected value，但评分权在主脑，后台只提供情境、精度与不确定性。

2.5 记忆的延展：外部存储

笔记、日历、照片、工具、他人都是外部记忆；内部记忆求“少而准”，外部记忆求“全而可查”，用指针连接，并保留来源、版本与删除权。延展心智是功能分工，不是本体论结论；外部存储不等于个体的记忆，除非它被情境包选中并参与决策。

2.6 机制背景：身体、社会与状态

人类记忆的显著性有“身体分量”和“社会分量”：内感受把能量、疼痛、威胁映射为需求；社会稳态把接纳、排斥、可依靠性映射为安全。它们解释的是“为什么这些事件更重要”，不是给机器装一套生理器官。

机器不维护 body_state，也不推断用户的身体状况；系统只从事件中抽取目标压力、关系张力、资源负荷、不确定性、预测误差与精度。人类机制只作为背景，工程主线从 2.7 开始。

2.7 事件影响与状态参数

2.7.1 事件影响状态：state_view 与 state_params

“状态”不能只是一行 prompt。如果它只出现在上下文里，它就是提示词——模型可以忽略、覆盖、改写。要让状态成为真的，必须拆成两层：

state_view：给主脑读的情境摘要，进 ContextPacket。它是提示词的一部分，作用是让主脑知道“现在目标压力高、关系张力大、还有未完成承诺”。

state_params：给调度器、检索器、网关、写入队列读的参数。它不在 prompt 里，而是改变系统的实际行为：检索多宽、验证多严、走快路还是慢路、什么必须入包、什么不得写入。

system_state = {
  goal_pressure, relationship_strain, resource_load,
  uncertainty, unresolved_commitments, coping_capacity
}
impact_gap = goal_pressure + relationship_strain + resource_load
             + uncertainty - coping_capacity

state_view   = summarize(system_state)      # 进 ContextPacket，给主脑读
state_params = map_to_params(system_state)  # 进 runtime，改变实际行为

状态高值时的参数变化作用点

举例：goal_pressure 高、resource_load 高时，系统应自动收窄检索、允许习惯快路、把未完成承诺钉在包里；这不是靠一句“请优先处理目标”，而是靠 state_params 改掉 top_k、预算与门控。反过来，uncertainty 高时，应扩大候选、提高 VERIFY 比例、允许弃权，而不是让模型“再想想”。

规则：state_params 由确定性规则从 system_state 推导，必须落日志、可复现、可审计；state_view 可以由模型摘要，但必须带 provenance。两者冲突时，以 state_params 为准——模型可以读到一句错误的状态描述，但不能因此绕过检索与权限参数。

这也给出 state_bias 的正确含义：它是由当前情境状态造成的解释偏移，不是机器自身的状态异常。状态性解释只能作为情境证据，不能直接更新关系特质；特质更新仍走 3.7 的提案—批准。

2.7.2 state_params 配置 schema 与测试口径

要让 state_params 不只是另一段文字，它必须是有 schema、有边界、有版本、可测试的运行时配置。推荐把参数收敛到五组，避免“状态”变成一堆散落的魔法数字：

state_params = {
  schema_version, params_version, derived_at, state_hash,
  retrieval: {
    top_k: 4..20, goal_weight: 0.0..1.0, candidate_mult: 1..4
  },
  audit: {
    verify_ratio: 0.0..1.0, abstain_threshold: 0.0..1.0,
    source_strictness: 0.0..1.0
  },
  scheduler: {
    fast_path: bool, depth: 1..3, max_tool_calls: int
  },
  context: {
    slots: 4..5, token_budget: 600..2000, pin_commitments: bool
  },
  memory: {
    encode_threshold: 0.0..1.0,
    consolidation_priority: 0.0..1.0,
    forgetting_exempt: [event_id]
  }
}

映射规则要确定性、有界、可复现。下面只是示例，真实实现应把权重写进配置并做回归测试：

top_k          = clamp(12 - 8*goal_pressure + 4*uncertainty, 4, 20)
goal_weight    = clamp(0.3 + 0.5*goal_pressure, 0, 1)
verify_ratio   = clamp(0.2 + 0.6*uncertainty + 0.2*relationship_strain, 0, 1)
abstain_thresh = clamp(0.5 - 0.3*uncertainty, 0.1, 0.8)
fast_path      = resource_load > 0.7 and uncertainty < 0.4 and impact_gap < 0.5
depth          = 1 + (uncertainty > 0.5) + (impact_gap > 0.7)
encode_thresh  = clamp(0.6 - 0.3*impact_gap, 0.1, 0.9)

理论边界 预测加工、延展心智、内感受/稳态、社会稳态/依恋都是宽泛的研究纲领，不是单一、已被完全证伪的理论；它们适合作为设计启发与统一语言，不能当作“脑就是这样”的最终结论。工程上仍要用消融与行为指标验证每一处映射。
边界声明 以下所有“脑区→Agent”的映射都是功能类比，不是神经解剖学的等价物。我们借用的是计算问题与约束，不是生物学本体。
