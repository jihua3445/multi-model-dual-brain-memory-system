The One-Page Proposal

The conclusion first: what must be simulated is not “memory”, but the loop between memory and decision.

The primary purpose of this proposal is not to build another memory store, but to let multiple models divide the labor so that the context the Main Brain must read each round is compressed to a minimum, while the information that does enter the context becomes more accurate. The human brain is not one large model; it is many functional units processing separately, with a single Main Brain making the unified judgment. The reason memory exists is to help the individual see clearly its relationships and position with others. Every mechanism below serves this through-line: division of labor → context → judgment → relationship and memory update.

THROUGH-LINE

Multi-model division of labor → the Backend compiles context → the Main Brain judges → relationship and memory update. Memory is not the goal; it is the infrastructure that lets the Main Brain make better judgments within relationships.

CORE THESES

The unit of memory is the Event, not the token; the reason memory exists is social relationships; the unit of context is the few blocks needed right now, not all of memory; the KPI is not “how much was stored” but “how many fewer errors in the next judgment within a relationship”.

FIRST-PRINCIPLES ABSTRACTION Events affect state; state affects judgment and memory. Humans, machines, and large models share the same principle; they differ only in the carrier of state and the speed at which it updates. State must be split into state_view (enters the context, is the prompt) and state_params (enters the runtime, and genuinely changes retrieval, budget, gating, and writing).
ARTICLE 0 Division of labor, not model stacking. Multiple models each handle a small slice, and a single Main Brain makes the unified judgment; otherwise you have merely traded one large context for a crowd of small contexts.

Ten Design Principles

  1. Multiple systems, not multiple copies. Episodic memory, semantic memory, procedural memory, working memory, and relationship memory are stored separately and updated separately; a single experience can produce three kinds of accumulation at once, but they share one Event source.
  2. Encoding has a threshold. Not every input is worth remembering. Salience, goal relevance, social impact, emotional intensity, and prediction error jointly determine whether an engram is allocated.
  3. Index and content are separate. The hippocampus does not store the whole film, only a sparse index; the system likewise does not stuff full text into the index, only pointers, sparse codes, and association weights.
  4. Consolidation is offline distillation. Encode by day, replay by night: scan—cluster—replay—abstract—merge—prune, distilling episodes into semantics and skills.
  5. Retrieval is reconstruction. Every answer is a narrative reassembled from fragments and must carry sources; where there is no source, abstain rather than fabricate.
  6. Reconsolidation is versioning. Every retrieval may rewrite memory; new versions are appended, old versions are retained, and nothing is overwritten.
  7. Forgetting is a feature. Decay, interference resolution, and index pruning jointly reduce noise; unfinished commitments and safety-critical information are exempt.
  8. Decision-making is dual-system. When familiar, low-risk, and time-pressured, take the habitual fast path; when novel, high-risk, and requiring explanation, take model-based deliberation. Arbitration belongs to the Main Brain.
  9. Relationships are the master index of memory. Person–Event evoke each other bidirectionally; relationships are multi-dimensional, asymmetric, evidence-bearing, and updated with time and experience.
  10. There is only one integrating center — and it belongs to the whole organism. The Backend only compiles context: it does not offer advice, does not act, and does not decide in place of the Main Brain. The external acting identity belongs to the organism, and the Main Brain signs on its behalf within the authorized scope.
ARTICLES 11 AND 12 (IMPLICIT) Boundaries are material, not policy; the ratification right is the ownership right. A constitution without runtime isolation is only a soft constraint; facts may be written by the Backend, but values/roles, goals, and habit rules are proposal-only, ratified by the Main Brain as the integrating organ, and the constitutional core requires equal co-signature by the user and the Main Brain. The execution mechanisms are in sections 3.6–3.7.

Relation to Versions One and Two

Versions One and Two established the skeleton of “one integrating center, backend brains, knowledge/memory/skill, relationships and experience, dual-brain decision-making”. The current version keeps this skeleton but introduces three kinds of change: retained and elaborated, revised, and added. Revisions and additions must be marked, so that later discussion is not mistaken for the original formulation.
