Simulation Details of the Key Mechanisms

Eight mechanisms, eight blocks of pseudocode; each comes with a guardrail that keeps it from degenerating into ordinary RAG.

The following eight sections are the "hardest" part of the whole proposal. They answer the same question: if descriptive knowledge from neuroscience is translated into rules an engineering system can execute, exactly which parameters, which judgments, and which boundaries must be written down? If you implement only three of them, start with the hippocampal index, the source audit, and offline consolidation — they correspond respectively to "findable", "trustworthy", and "smarter with use".

6.0 Evidence grading and how to read it

  • A · Human intervention / lesion:can directly support a "mechanism conclusion".
  • B · Animal causal:can support a mechanism hypothesis, but the species and paradigm must be stated; it cannot be extrapolated directly to humans.
  • C · Human correlational / behavioral:can only be written as "consistent with human behavior", never as causation.
  • D · Computational / design metaphor:can only be written as a "design heuristic", never as "this is how the brain works".

Mapping:6.1 B/C; 6.2 B/C; 6.3 B; 6.4 C/D; 6.5 D; 6.6 A/B; 6.7 B/C; 6.8 C/D. Only A/B may be written as a "mechanism conclusion"; C is written as "consistent with behavior"; D is written as a "design metaphor". Specific numbers given in the text without a grade are engineering defaults, not neuroscience measurements.

6.1 Hippocampal index: sparse codes, pattern separation, pattern completion · evidence grade B/C

Mechanism recap.The hippocampus is not a warehouse but an index; the dentate gyrus separates similar inputs (pattern separation), and CA3 completes a whole from a partial cue (pattern completion). The balance between the two determines whether memory can both distinguish details and generalize from one case to many.

Sparse code.For each event, an encoder produces a feature vector x, followed by k-winner-take-all: keep only the strongest k dimensions (for example 32/512), zero the rest, and obtain a binary sparse code s. The sparse code is not a summary but an "index fingerprint": it does not answer content, it only lets similar cues find the same episode.

# event index
x = encoder(event_text, participants, scene, goal, affect)
s = topk_mask(W_e @ x, k=32)          # sparse binary code
trace = {
  event_id,
  code: s,
  tags: [person_ids, place, topic, goal, affect],
  edges: [(person_id, weight), (event_id, relation), ...],
  threshold: calibrated_threshold
}

Pattern separation.When a new event's cosine similarity to an existing event exceeds θ_sep (for example 0.86) but time, place, goal, outcome, or participant state differ, the system must force a new event_id and write discriminating tags and a different_from edge. Typical cases: three quotes for the same client, two reviews of the same project, two commitments by the same person. Merging them into one is the most insidious and most fatal error a memory system can make.

if cos(e_new, e_old) > θ_sep and context_diff(e_new, e_old) > τ:
    e_new.id = new_event_id()
    e_new.tags += discriminative_tags(time, place, goal, outcome, participant_state)
    graph.add_edge(e_new.id, e_old.id, type="different_from", reason=...)

Pattern completion.Retrieval starts from the cue and performs multiple rounds of expansion and reranking. Round one uses vector nearest neighbors to find semantic similarity; round two expands along person, place, causal, and temporal edges; round three prunes with consistency constraints. Each round's score is a weighted sum, and it stops when the last round converges or the budget is reached.

C = parse_cues(query)                    # person/time/place/topic/goal
for r in 1..R:
    N = vector_topk(C, k=50) ∪ graph_neighbors(C, hops=2)
    score = 0.35*cue_overlap + 0.25*assoc_weight + 0.15*recency
          + 0.15*salience + 0.10*source_reliability - 0.20*interference
    C = topk(N, score, k=12)
    if converged(C): break
return C
GuardrailPure vector similarity can only show that things are "semantically related", not that "this happened". Episodic recall must be supported by at least one structural edge (person, time, place, causality); otherwise it may be labeled only as "semantic association", never as "memory".

6.2 Sleep replay: translating "slow oscillation — spindle — ripple" into batch processing · evidence grade B/C

Mechanism recap.In NREM sleep the slow oscillation governs the global rhythm, spindles pack local information, and ripples drive replay of hippocampal sequences; the three are coupled, redistributing the day's experience to the cortex and running important fragments "overnight" repeatedly.

Batch mapping.Do not turn "sleep" into a random summarizer; make it a three-layer schedule:

Table 10 · Three-layer mapping of sleep rhythms to batch processing
Neural rhythmFunctionBatch layerOutput
Slow oscillation 0.5–1 HzGlobal scanning, up/down state phasingScan: traverse the day's events, ordered by priorityReplay queue
Spindle 11–16 HzLocal packing, cortical plasticity windowCluster: group by person/project/theme, pick representativesTheme bundles
Ripple 100–200 HzSequence replay, memory consolidationReplay: replay "cause→action→outcome", generate counterfactualsSummaries, lessons, skill candidates
 
# nightly consolidation batch
events = load_events(last_24h)
priority = salience^0.8 * (1 + prediction_error) * (1 + goal_relevance) * (1 + unresolved)
clusters = cluster_by(events, key=[person, project, topic], method="graph+embedding")

for cluster in clusters:
    seq = order_by_causality(cluster)
    replay = summarize_sequence(seq)                    # cause→action→outcome
    counterfactual = generate_alternatives(seq)         # what if ... at the time
    lesson = extract_lesson(seq, counterfactual)
    if evidence_count(lesson) >= 2:
        propose_knowledge_or_skill(lesson, source_event_ids=seq.ids)
    propose_relationship_update(cluster.persons, seq)   # constitutive: proposals only
    compress_ordinary_interactions(cluster)
prune_low_retention_indexes()

Write-back boundary.Events, facts, explanation candidates, and skill candidates go through the fact-writer; relationship weights, habit rules, goals, and values only produce a ConstitutiveProposal, which passes a source/constitution audit and enters the pending-ratification queue, taking effect only after ratification. The consolidation stage has no authority to "directly rewrite the future self".

Priority.Replay is not "newest first" but "most useful for the future first": events with high salience, high prediction error, ties to unfinished goals, or repeated access without abstraction go first. Ordinary small talk, repeated confirmations, and consequence-free routine should be compressed into phase summaries rather than replayed item by item.

Frontier addendum (2025).Replay is not uniformly distributed across the night but is organized by sleep microstructure (Chang et al. 2025). In engineering terms, the offline batch should be split into nested windows: global scan (slow wave) → local packing (spindle) → event replay (ripple), rather than one summary at the end of the night.

GuardrailThe consolidation stage is where stories get invented most easily. Every abstract conclusion must carry source_event_ids; a conclusion supported by fewer than two independent events may be labeled only as a "hypothesis" and may not be promoted to knowledge or skill; habit rules, relationship weights, goals, and values must not take effect directly during consolidation. Counterfactuals may be used only to generate candidates, never written as facts.

6.2.1 Compositional replay: constructing future candidates from past elements

Faithful replay consolidates the past; compositional replay extracts elements (person, place, action, outcome) from at least two events, recombines them under causal, social, and physical constraints, and generates future candidates. Research published in Nature Neuroscience in 2025 further indicates that the hippocampus decomposes experience into reusable primitives and then recombines them into new state spaces; replay participates in building and consolidating these combinations (Bakermans et al. 2025). The implication for the system: compositional replay should maintain a primitive library (person, place, action, relation, goal); otherwise it can only recombine existing elements and will struggle to generalize to new situations. It is not memory: it writes no event log, counts as no evidence, and outputs are tagged source=compositional_replay, is_fact=false, offered to the Main Brain as options only.

Primitive { kind: person|place|action|relation|goal, id, value, tags }
compose_from_primitives(library, slots=["person", "action", "goal"])

Composition samples by slot type: a person slot may hold only a person, a place slot only a place; the same primitive can be reused across events. What is generated is thus an "unseen combination", not a permutation of existing sentences. Only after the Main Brain adopts it and acts, and the real outcome is observed, does the outcome become a direct event; the candidate scenario itself is never upgraded to a fact.

Evidential boundary of schema.Schema compatibility accelerates consolidation; this is the classic conclusion of Tse et al. (2007). But direct evidence from 2024–2026 remains limited. Currently it is treated only as a qualitative principle: schema_fit is not written as a hard parameter, and in the retention formula it is only an optional input that does not change the main path.

6.3 Reconsolidation: version chains and prediction error · evidence grade B

Mechanism recap.Retrieval renders a memory labile; if a prediction error or new information appears, the memory is updated and then reconsolidated. Without a prediction error, retrieval merely makes the memory more accessible and does not necessarily rewrite its content.

System mapping.Implement "reconsolidation" as event sourcing + version chains, not as "overwriting the old summary with a new one". Each retrieval records an access; when new information conflicts with the old record, or the outcome deviates significantly from expectation, create a new version:

old = get_event(eid)
access_log.append(eid, now, cue, context)

pe = abs(old.expected_outcome - observed_outcome)
novelty = 1 - cos(embed(new_info), embed(old.summary))

if pe > θ_pe or novelty > θ_novelty:
    v = old.clone()
    v.version = old.version + 1
    v.supersedes = old.id
    v.content = integrate(old, new_info)
    v.basis_event_ids = old.basis + [new_event.id]
    v.confidence = calibrate(v)
    store.append(v)                      # old version retained
    graph.add_edge(v.id, old.id, type="supersedes")
else:
    old.last_accessed = now
    old.access_count += 1

How to set the thresholds.θ_pe and θ_novelty should not be fixed constants but adjusted by memory type: contract terms, commitments, and medical information use low thresholds (prefer more versions); general preferences and small talk use high thresholds (avoid over-rewriting). This amounts to giving different memories different "plasticity".

Boundary of the frontier evidence.Evidence from 2024–2026 on how memory age/intensity modulates reconsolidation remains inconsistent; the current implementation therefore keeps only θ_pe / θ_novelty and does not introduce additional hard thresholds for age or intensity. Age and intensity are treated as parameters awaiting verification, not as rules.

GuardrailLow-trust sources (hearsay, anonymous messages, model inference) cannot directly trigger a "fact version" update; they can only create a "candidate explanation" that waits for a second independent source. Reconsolidation is updating, not credulity.

6.4 Forgetting: the retention formula and the exemption list · evidence grade C/D

Mechanism recap.Forgetting arises from decay, interference, retrieval failure, and active suppression; it reduces the interference of old information with new learning and supports generalization. The memory trace may still exist; it has merely become hard to retrieve.

Retention.Use an interpretable multiplicative formula that places "time, reliable recurrence, emotion, utility, relationship strength" together. Only recurrence from a reliable source increases stability; low-trust recurrence raises accessibility only, not stability:

R(t) = exp(-Δt / S)
       * (1 + α * |valence|)
       * (0.5 + 0.5 * utility)
       * (0.5 + 0.5 * relationship_intensity)

n_eff = distinct_retrievals * source_reliability
S = S0 * (1 + β * n_eff)
       * (1 + γ * schema_fit)
       * (1 + δ * arousal)

Where reliability comes from.It is computed by reliability.py over four dimensions: source-type prior, verifiability, historical calibration (Laplace smoothing), and consistency with corroboration. It is a prior, not ground truth; a low-reliability source may still be right, so it is not deleted — it is only prevented from becoming "steadier the more it is recalled". Historical calibration comes from EvidenceLedger.record_outcome: when a source's claim is later confirmed or refuted, its accuracy is updated.

Exemption list.The following content does not take part in decay, or is down-weighted but never deleted: unresolved commitments, safety-critical information, content the user explicitly asked to remember, legal/compliance retention items, and the context of ongoing projects. Exemption is not "permanent storage" but "must be explicitly lifted by the Main Brain or the user".

Handling interference.Two conflicting memories are not averaged, nor is the newer one chosen automatically; both are kept, a contradicts edge is added, and both are returned at retrieval with source and time annotated. Letting the Main Brain see the conflict is safer than the system quietly splitting the difference.

GuardrailForgetting acts only on the "active index" and does not physically delete the raw event log; physical deletion is triggered only by the user exercising the "right to be forgotten" or by a compliance process, and leaves an audit record.
