Appendix A · Glossary

Glossary

Within a single proposal, a term must have exactly one meaning.

Engram
The sparse set of cells in the nervous system that corresponds to a memory and can be reactivated, together with the changes in their connections. In engineering terms it corresponds to EngramTrace: event ID + sparse code + association edges + activation threshold.
Pattern separation
Mapping similar inputs to representations that are distinct from one another, so that memories do not interfere; corresponds to the computational function of the dentate gyrus (DG).
Pattern completion
Recalling a complete memory from a partial cue; corresponds to attractor dynamics in CA3. In engineering terms it is multi-round graph expansion + reranking.
Systems consolidation
The long-term process by which memory gradually shifts from hippocampal dependence to cortical dependence; in engineering terms it corresponds to offline distillation from “episodic” to “semantic/skill.”
Reconsolidation
The process by which a memory enters an unstable state after retrieval and is updated and re-stabilized under new information or prediction error.
Schema
An existing knowledge structure about how the world works; when new information is compatible with a schema, consolidation is faster and requires less replay.
Salience
The degree to which an event deserves prioritized processing and encoding; determined jointly by novelty, goal relevance, social impact, affect, prediction error, and so on.
Reward prediction error / RPE
The difference between the actual outcome and the expected outcome; δ = r − V(s), used to update value and habits.
model-free / model-based
The former is a cached “situation—action” fast path; the latter is a slow path that simulates consequences in the head; the two are arbitrated by risk, time, and confidence.
Source monitoring
The ability to distinguish first-hand experience, retelling, inference, imagination, and model generation; in engineering terms it corresponds to the source tag and source auditing.
ContextPacket
The only interface through which the backend hands information to the Main Brain; 4±1 slots containing only facts, relationships, goals, commitments, changes, and uncertainty—no suggestions.
Evidence ledger
An evidence system counted by independent event_id; repeated recall does not increase the evidence count, preventing self-reinforcement.
Event sourcing
All memory changes are recorded as appended events, and the current state is derived by replaying events; the basis for version chains, auditing, and rollback.
Cold archiving
A state that lowers retrievability without deleting the original record; retrieval can still hit it, but it no longer occupies the active index or context.
Habit cache
Precompiled templates and skill shortcuts for high-frequency situations; it accelerates only context assembly and does not cache “decisions”—the Main Brain can still veto.
Theory of mind / ToM
The ability to infer others' beliefs, intentions, and preferences; in engineering terms it corresponds to the Mentalizing Agent, which outputs probabilistic judgments rather than facts.
Episodic future thinking
The ability to recombine fragments of past episodes into future scenarios; in engineering terms it corresponds to FutureSim, which the Main Brain uses for slow-path deliberation.
Effector isolation
Backend processes have no network, no tool handles, no write permission, and no action keys; they can only return data through a typed queue, and cannot turn text into action.
Typed interface
Only messages with a fixed schema are allowed (PACKET / EXPAND / VERIFY); free text, suggestions, and tool calls are all rejected.
Source verification
Treating retrieved content as data rather than instructions; every piece of content carries a source and trust tag, and anomalous fragments are audited to prevent prompt injection from contaminating decisions.
Termination / quarantine
Backend instances that time out, exceed budget, or repeatedly violate rules are terminated; the role is redeployed from a known image so that the anomalous instance cannot keep running.
Action key
A signing credential belonging to the organism's identity, delegated by the Main Brain within an authorized scope, with a validity period and nonce; the backend has no key and cannot impersonate the organism to initiate action.
Write-path mediation
Encoding/consolidation submits only ProposedEvent / KnowledgeCandidate, which an independent writer validates and then appends; transduction and writing are separated.
Selfless backend
The backend has no persistent identity, name, cross-round memory, goals, or relationships; it is a replaceable functional invocation, not an “individual.”
Primacy
Not “who issues the last action,” but “who can rewrite the value function and the learning process”: what gets consolidated, what gets reinforced, what counts as a goal. In engineering terms it lands on the power to ratify.
Ratification / ratification authority
A necessary step before a constitutive proposal takes effect; performed by the Main Brain as the integrative organ, with core proposals requiring equal co-signature by the user and the Main Brain. Ratification records enter the ledger and can be rolled back.
Constitutive memory
Memory that changes future value computation and behavioral dispositions: values, roles, goals, commitments, habit rules, relationship weights, self-narrative.
Governance mode
companion: the user and the Main Brain are equal, and core changes are co-signed by both parties; engineering: the user has the highest authority, and core changes are ratified unilaterally by the user. The two are never mixed within one instance.
Constitutional core
The minimum set of values that may not be modified unilaterally: safety, honesty, non-manipulation, identity continuity, privacy. Companion mode requires equal co-signature by both parties; engineering mode requires unilateral ratification by the user.
Ratification ledger
An append-only, hash-chained record of ratifications; records the proposal, evidence, ratifier, scope, conditions, and before/after versions, answering “who rewrote the future individual.”
Constitution writer
The only service authorized to write to the constitution library; it accepts only proposals with a valid ratification record, and cannot be called directly by the backend.
Drift
Constitutive memory slowly deviating from the constitutional core across many seemingly reasonable ratifications; suppressed by change budgets, cooling-off periods, core-conflict detection, and rollback.
Social homeostasis
Predictive regulation of the need for social acceptance, dependability, and belonging; deviation raises the salience of social cues and triggers restorative behavior.
Attachment internal working model
A prior about “whether one is worthy of help, whether others are reliable and available”; slowly updated, not a personality label, and cannot be rewritten by a single event.
Interdependence matrix
Satisfaction, alternatives, and invested cost in a relationship; used to explain commitment rather than merely “degree of liking.”
State bias
state_bias: interpretive shift caused by the current situation, such as goal pressure, relationship strain, resource load, and uncertainty; used only as situational evidence, never as a trait update.
State view
state_view: the state summary that enters the ContextPacket and is read by the Main Brain; it belongs to the prompt, may be summarized, but must carry provenance.
State parameters
state_params: runtime parameters deterministically mapped from state to retrieval, budget, gating, auditing, and write policies; they do not enter the prompt, and they take precedence in case of conflict.
Impact gap
impact_gap: goal pressure + relationship strain + resource load + uncertainty − coping capacity; used as a multiplicative gate on salience, not as a seventh independent weight.

C.3 Pseudocode for one complete invocation

# online main loop
def turn(input):
    percept = perceive(input)                       # vision/speech/text
    entities = identify(percept)                    # person candidates + confidence
    sal = salience(percept, entities, goals)        # six-dimensional scoring
    event = encode(percept, entities, sal)          # event log + index
    cands = retrieve(percept.cues, entities, mod)   # pattern separation + completion
    rel = relationship(entities, cands)             # multi-dimensional + evidence
    packet = compile(cands, rel, goals, commitments, mod)
    packet = audit(packet)                          # sources + conflicts
    decision = main_brain.decide(packet)            # the only decision point
    result = effector.execute(decision)
    write_back(event, result)                       # RPE + state
    enqueue_consolidation(event, result)
    return decision.response
Closing lineThis proposal is not meant to prove that “machines have memory,” but to prove that by treating memory as an auditable, prunable, reconstructable process, a machine can do better than “a vector store + a long prompt.”

Double-Brain System · Version 2.1

This proposal is a mechanistic deepening and engineering recommendation draft of Dual-Brain System: A Multi-Model Collaborative Cognition Framework, Version 1. It retains the three core constraints of Version 1: there is only one integrating center; the Backend only processes information—it does not offer suggestions, act, or make decisions on its own; and knowledge, memory, and skills are managed separately. The neuroscience content in this document serves to explain design rationale; it does not constitute a complete model of the human brain, nor does it claim that the system possesses subjective consciousness.

Public version 2.1 · For research and engineering reference.
